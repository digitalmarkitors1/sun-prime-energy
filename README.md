# Sunprime Energy Solutions — website + CMS

Next.js 16 static site (`output: "export"`) hosted on Hostinger, with a
Supabase-backed admin CMS for editing all page content and SEO.

## How it works

- **Content** lives in Supabase and is mirrored to `data/*.ts` (which the static
  build reads). If Supabase isn't configured, the committed `data/*.ts` files
  are used as-is — the site always builds.
- **Editing** happens at `/admin` (a browser-only dashboard that talks straight
  to Supabase). Saves are instant to the database.
- **Publishing** regenerates `data/*.ts` from the database, rebuilds the static
  site, and zips it for upload to Hostinger.

```
/admin (edit, save)  →  Supabase  →  npm run publish (pull + build + zip)  →  upload to Hostinger
```

## Local development

```bash
npm run dev        # http://localhost:3000  (admin at /admin)
```

## One-time Supabase setup

1. Create a Supabase project. Copy the URL + anon key + service_role key into
   `.env.local` (see `.env.example`).
2. In the Supabase SQL editor, run `supabase/migrations/0001_init.sql`.
3. Create the admin login: Supabase → Authentication → Users → **Add user**
   (email + password). That's the login for `/admin`.
4. Seed the database with the current site content:
   ```bash
   npm run seed
   ```

## Editing content

Go to `/admin` and sign in. Tabs:

- **Site content** — every section of the site (contact, services, industries,
  projects, founder story, FAQs, the 43-project list, etc.).
- **Landing pages** — the 11 SEO landing pages (content + per-page meta).
- **SEO** — title / description / canonical / OG / noindex per standard route.
- **Media** — upload images and copy their URLs into image fields.

Save as you go. Nothing is live until you publish.

## Publishing to Hostinger

```bash
npm run publish
```

This pulls the latest content from Supabase into `data/*.ts`, runs the static
build, and produces `sunprime-site.zip`. Then in **Hostinger File Manager**,
open `public_html`, remove the old files, and upload the **contents** of the zip
(equivalently, the contents of the generated `out/` folder).

## Scripts

| Command           | What it does                                              |
| ----------------- | --------------------------------------------------------- |
| `npm run dev`     | Local dev server                                          |
| `npm run build`   | Static build from committed `data/*.ts` (no DB pull)      |
| `npm run seed`    | Push current `data/*.ts` content into Supabase (one-time) |
| `npm run pull`    | Regenerate `data/*.ts` from Supabase                      |
| `npm run publish` | `pull` + `build` + zip for Hostinger upload               |

## Notes

- Without `.env.local`, `/admin` shows a setup screen and the site builds from
  the committed data files.
- `data/site.ts`, `data/landingPages.ts`, and `data/seoDefaults.ts` are
  regenerated by `npm run pull`; their committed versions act as the fallback.
- `/admin` is `noindex` and disallowed in `robots.txt`.
